# Liftwise v1.2.1 — Unified streak and iPhone polish

This release incorporates the unpublished UI consolidation candidate and fixes
the streak discrepancy. It consolidates the existing application around AppShell and
AppHeader. Home, Plan, Workout landing, Progress, Settings and Exercise Library
share title and compact streak placement, without the App Wordmark. ContextToolbar supplies builder
and Progress detail geometry; ContextBackLink supplies contextual return behavior.
The focused workout logger retains its dedicated training controls.

Recovery Day uses smaller artwork, concise copy and actions in document flow.
Schedule Settings keeps labels with their controls; Plan heroes and Exercise Detail
use compact typography and spacing. Builder stages, saved drafts, prescriptions,
workout calculations, backup v2, database v6 and PWA identity are unchanged.

The package manifest and `src/app/version.ts` are authoritative version references.
The pnpm lockfile has no root application version field; manifest identity and
service-worker metadata are generated by the existing build and need no version edit.

## Layout and data ownership

- AppShell applies horizontal safe areas and content/navigation clearance.
- AppHeader applies the top inset once; focused logger routes apply it to main
  instead because they omit the global header.
- BottomNavigation includes the bottom inset in its measured height. Its observer
  supplies the shell clearance even when navigation typography grows.
- Home and Progress retain their owning loader snapshots. The shell loader calls
  the existing ProgressRepository.streak() for Plan/Workout landing and remaining
  general and detail routes. All streak consumers use the same repository projection.
- No extra storage, streak calculator, polling, PWA, entry point or dependency.

## Streak root cause and correction

Progress and History previously called calculateStreakStats directly with weekly
training days, omitting the flexible-cycle rest predicate supplied by
ProgressRepository.streak(). A recovery gap could therefore break the Progress
streak while Home correctly preserved it. Those loaders now call the repository
with the same clock and an optional missed-day period boundary. Lifetime current
and best counts, local completion dates and duplicate-day handling are unchanged.

Historical dates before a cycle's start are not excused as rest, so starting a new
program cannot inflate past or current runs. An unavailable loader snapshot is
shown as unavailable rather than a genuine-looking zero. Regression coverage also
requires real destination navigation offline and actual content/nav-clearance
checks, avoiding empty matches that could pass without checking the screen.

Eligible attendance is a valid completed workout; opening/reloading the app does
not write attendance. Calendar date labels and connections reflect real completed
days only. The schedule calendar retains its deliberately assigned workout dates,
including sessions spanning midnight; it is not a second attendance counter.
There is no account or login flow to change or test.

## Verification

Release checks and browser results are recorded in `UI_CONSOLIDATION_AUDIT.md`.
Automated Playwright WebKit uses the eight requested portrait viewports and
injected safe-area values. It does not reproduce a physical iPhone keyboard,
Dynamic Island, installation lifecycle, VoiceOver or storage eviction.

The user supplied physical-iPhone screenshots of the previous interface. This
release has not been tested on a physical iPhone. Follow `IPHONE_TESTING.md` for
post-release device acceptance; retain external backups for gym-soak testing.
